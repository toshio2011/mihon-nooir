# Windows Wi-Fi transfer — November 18, 2026

Draft Windows-only feature stacked on #88. The [Folio Nooir HTTP endpoints](https://github.com/toshio2011/folio-nooir/blob/main/docs/webserver-endpoints.md) document GET /api/files, POST /upload multipart, and exact text acknowledgment. Sender uses an explicit private IPv4 address and existing folder; no mDNS discovery, automatic upload, rename, delete or firmware changes. It reuses the existing Android transfer-only 180 MiB policy unchanged. It refuses observed case-insensitive collisions before upload, disables proxy/redirects, streams bytes, requires the documented acknowledgment, then re-lists and checks exact filename and file length. The firmware can overwrite: simultaneous writers are not transactionally excluded; use a single sender. File-size verification is not content hashing or reading validation. Local mock tests only; actual reader transfer not yet validated. A failed upload can leave a partial reader file. Keep reader on File Transfer and use trusted LAN/hotspot. This initial UI sends one already-existing local book, not automatic conversion-to-device, and requires explicit confirmation. No Android or firmware mutation.

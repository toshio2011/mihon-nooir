## 1. What the user wants (the authoritative behavior)

**Repository:** https://github.com/toshio2011/mihon-nooir  
**Roadmap / engineering notes:** https://github.com/toshio2011/mihon-nooir/issues/8  
**Firmware reference — read only for this work:** https://github.com/toshio2011/folio-nooir

MihonNooir is the **existing full Mihon Android manga reader** plus EPUB / CBZ / XTC / XTCH conversion and e-reader transfer, not a separate Android app. Preserve normal Mihon library, sources/extensions, reader, downloaded chapter storage, updates and backup workflows, quick online chapter export, queue, metadata, covers, source chapter selection, and all other tools. Android app package remains `dev.nooir.mihon.foss`; user uses an Android 16 phone. A new test APK's certificate might differ from the installed APK; back up data before making installation changes, and do not bypass Play Protect warnings.

**Panel export design:**
- **Panel by Panel**: ideally one *meaningful illustrated panel* per screen, but never clip balloons, artwork or text. Favor complete coverage and conservative intact-page/row fallback over speculative cuts. Output may be larger.
- **Row by Row**: retain each horizontal tier together; **this mode currently works better in real Conan testing and must not change as collateral damage**.
- **Full Page Before Splits**: intentional user selection, NOT an accidental duplicate. Preserve the original full page before multiple legitimate detail views when enabled; do not remove it just to lower the frame count.
- **Auto Fit**, orientation, RTL for Japanese manga, overlap, original source pixels and guard padding are important. No OCR, paid AI, obligatory review of hundreds of pages, remote processing or device-side panel segmentation.
- Main target XTEINK X3/X4 + Folio Nooir; conversion executes on the phone. EPUB 2, EPUB 3, XTC, XTCH, CBZ continue through existing shared writers. Windows uses shared core detector/converter where possible; don't create a divergent simplified algorithm.
- **User tests actual EPUBs and expects the assistant to inspect output**, not declare success solely from tests or GitHub green jobs. Never invent or guess an improvement from frame count alone.

**Current known defects in the 330-frame Panel EPUB:**

1. **P113–P114:** two mostly border-only frames remain. Corresponding **Row R78** preserves sparse framed content as **one intact frame**. Previous Panel P113–P116 was four nearly empty frames. Avoid deleting near-white frames without source-coordinate evidence: some legitimate title, splash, credits or end-matter screens are sparse.
2. **P143 / Row R96:** two illustrated story columns remain **grouped together**, output images were identical in comparison despite the shifted frame index (old P145 → new P143). A plausible interior divider exists in the **rendered** preview, but actual high-resolution source raster/thumbnail may differ. Need rejected candidate trace and exact source image.
3. **P311–P315 / Row R227:** a wide title/typography region gets split into overly magnified fragments of words, including parts of “Aoyama-San Won't Wake Up”. Technically retaining pixels is insufficient; this creates awful page-turning. Should avoid false positive panels from typography/lines, but without blanket “remove all sparse ink” filters.
4. Other intentionally sparse images occur around **Panel P183 / Row R131** and **Panel P310 / Row R226**. Do not assume all such frames are errors.
5. User deliberately requested **Full Page Before Splits**. Keep genuine overview frames.

**Validated:** EPUB ZIPs and image payloads were inspected; not a corrupted archive. The exact row reference R78 and R96 images remained pixel-identical across compared exports. **Not validated:** a fully corrected panel output, physical X4 reading, Android/Windows pixel parity, nor safe new public release.

Offline comparison helper: `python3 tools/panel_epub_diff.py "old panel.epub" "new panel.epub" --json -o panel-comparison.json`; see [PANEL_EXPORT_QA.md](PANEL_EXPORT_QA.md). It anchors by EPUB spine order and SHA-256 of embedded images. Frame positions shift as splits change, so do not interpret “P143” as a stable global source page ID. It cannot prove dialogue preservation or visual quality.

### Design and current attempted implementation

- **Toggle (default OFF):** in normal Export to e-reader dialog → More conversion settings → Panel by Panel → “Save panel diagnostics after this export.” A 20th settings token element was appended to `MangaConversionSettingsCore.kt`; old 7–19 element tokens should still decode unchanged and with debug off. The flag should reset for subsequent jobs but be retained by the queued job being exported.
- **Capture alongside the *normal* export**, including Mihon downloaded directories, CBZ and Quick Export. Avoid separate reprocessing if possible; diagnostic callback should be a no-op in ordinary mode. Diagnostic failure should not fail or alter the actual manga book.
- **Exact detector input:** store lossless grayscale thumbnail (the **byte values actually analyzed**), bounded to 600×900 by the Android adapter, rather than a screenshot of already quantized EPUB frames.
- **Per-input page JSON:** source/chapter ordinal only (no manga name or source URL), original decoded dimensions, thumbnail dimensions, detector regions, mapped source rectangles with padding, output slices and screen rotation, one-based output frame index (including optional separate cover and Full Page Before Splits), reasons for accepted/rejected seams, sparse tiers, fallback, retries, etc. Rectangle coordinates: [left, top, right, bottom), source vs thumbnail explicitly labeled.
- **Some unmodified source image bytes** for suspicious pages, not only resampled thumbnails (currently proposed caps: up to 24 originals, 8 MiB per image, 80 MiB total), and up to 3,000 captured pages / roughly 120 MiB ZIP size. Avoid saving everything at full res or blowing phone memory.
- **Private output:** in app-private storage `filesDir/manganooir_panel_debug/latest.zip`; only save a user-chosen copy with Android Storage Access Framework **Save latest panel diagnostics ZIP** in the export dialog. Never auto-upload, silently share, or embed in EPUB/CBZ/XTC/XTCH.
- **Privacy:** a ZIP can contain copyrighted/identifying *images*. Only share by explicit user decision and review; don't commit to public repo/issues or assume it is safe to post publicly. No OCR/AI/cloud required.

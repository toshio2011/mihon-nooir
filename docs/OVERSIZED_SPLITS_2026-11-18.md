# Oversized splits — cross-platform draft, Nov 18

Stacked on #93 (Windows installer acceptance all green). User approved Android and Windows enhancement. **Enlarge oversized splits** is a stored option, default on, fitted screen-fill threshold default 50%, adjustable 25–80%. Existing >60%-source-height Panel by Panel rescue remains eligible independently, but new speculative halves require actual linear zoom of at least 5% and non-sparse halves. New Row by Row only considers verified multi-row pages, >50% of source height, >=80% of source width, low fitted fill, no strong preexisting overlap or protected art; never detects inner columns, never splits uncertain whole pages. Halves each cover 56% of the source region with 12% repeated source height. Ordinary overlap is independent. Panel second-look validated structural detection remains before speculative overlap; toggle also gates historic no-boundary overlapping-thirds detector (separate heuristic, not fill threshold). Existing seam-based cuts are independent. Shared option token appends two fields; legacy decode supported. Windows now uses Android refiner, bitmap-specific second-look adapter, sparse and preserveWhole handling; exact pixel parity not yet proven. New tests: settings roundtrip/legacy migration, row zoom/coverage/protection, detector fallback disabled, real Windows XTC/XTCH oversized row on/off. Exact CI and physical example review pending. No merge, publishing, Android release or firmware changes.

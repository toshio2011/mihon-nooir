# Windows online manga reader — first transport slice (19 November 2026)

Draft, Windows only; based on the passing integrated extension-setup preview. Not a finished online reader.

Reviewed pinned upstream v2.4.2366: [ChapterMutation.kt](https://github.com/Suwayomi/Suwayomi-Server/blob/v2.4.2366/server/src/main/kotlin/suwayomi/tachidesk/graphql/mutations/ChapterMutation.kt) and [ChapterType.kt](https://github.com/Suwayomi/Suwayomi-Server/blob/v2.4.2366/server/src/main/kotlin/suwayomi/tachidesk/graphql/types/ChapterType.kt). The explicit fetchChapterPages mutation supplies ordered local page URLs, chapter metadata and a possible reading-sync conflict. Its server implementation can pull/update server-side KOReader progress according to configured sync policy; MihonNooir does not assume this operation is entirely read-only.

This slice validates chapter/manga identities, the count (1–5000), exact source-order/index paths, and progress before accepting a manifest. Each page is fetched only on demand over the existing localhost client, without redirects, arbitrary host URLs, CBZ download requests, app-written progress mutations or local file persistence. Encoded image bytes are limited to 25 MiB per reply; byte validation is not decoded-pixel safety. The future native reader must use dimension preflight, bounded decode, worker-owned cancellation, recoverable failures, explicit chapter opening and a clear sync-conflict/progress policy. No native online reader button or sync is shipped by this transport-only draft.

CI: synthetic loopback-only page API tests, no third-party extensions or copyrighted manga. Real pinned-server page contract still needs a lawful synthetic local-source fixture, followed by native UI acceptance and actual authorized source validation. Android and firmware remain unchanged.

## Native online reading follow-up

**Read chapter online** is now wired to exactly one selected chapter on the active server. The reader loads the selected manifest off the UI thread, fetches one page at a time, uses the existing dimension-bounded decoder and shared canvas, offers Previous/Next, page jump, fit page/width/original, zoom, right-to-left keyboard navigation, Retry and close. No entire-CBZ download or application-side progress write. The latest-only gate owns one in-flight worker; stale decoded bitmaps are flushed and closing discards queued work. A currently active network read is allowed to finish, not forcibly killed. Server sync conflicts are disclosed; server position is an explicit resume option when no conflict exists. Initial scope is single-page reading; online spread/webtoon, chapter transitions, progress persistence and full real-source acceptance remain follow-ups.

The real packaged Swing smoke test now drives the production main window from a synthetic localhost library/chapter through native reading, deliberate page failure, retry, page navigation and close. This does not claim real third-party source compatibility. Windows only; Android unchanged.

## Chapter navigation and local resume

The Windows reader now offers Previous chapter / Next chapter in the same window, using the current title's sorted chapter list. Chapter changes wait for the active page worker to settle, keep the former page on manifest failure, and resume the last successfully displayed page of each chapter. Automatic resume is desktop-local metadata under the configured data root (`online-reading-v1`), isolated by endpoint/chapter identity, names and page count. Metadata is atomically replaced; malformed data is retained and save errors are reported. No source images, credentials or server-side progress mutations are stored by this feature. Server conflict prompts remain informational; backend-configured sync behavior is unchanged. Same-endpoint database replacement or title edits can affect identity matching; cross-device sync and marking chapters read remain separate work. Native acceptance exercises two chapters, retry, in-window navigation and close/reopen resume; real third-party source testing still required.

## Implementation

## QA5 — user-suggested last-resort overlapping rows (5 Nov 2026)

QA5 is a **new**, separately installable experimental APK built from the head of draft PR #66, stacked on #64. Unlike QA4, after *all* existing detector passes fail on an otherwise illustrated portrait page, it can return three intentionally overlapping reading windows: top **0–40%**, middle **30–70%**, bottom **60–100%**, in that order. On each window only a strict clean full-height column gap may produce two left/right reading views. No confident inner panel boundary means keep the entire overlapping row; do not subdivide dialogue/art. All source coordinates are covered by the windows and overlaps are not controlled by the user's normal 0% export overlap setting. The source art is never polygon-clipped.

This is a **readability fallback, NOT verified panel recognition**. The eligibility screen checks rich balanced thumbnail content in every third (illustration, pale paper, and edge variation), and keeps cover/title/sparse/text/monochrome and long-strip content in existing modes. Private preflight from 201 user-supplied One Piece thumbnails predicts 37 candidates among the 45 formerly fully unsplit pages, but neither a Kotlin rerun nor real EPUB export has yet confirmed this number. Any false cut on a splash or speech bubble is a blocking regression. Keep this PR and its base unmerged; obtain same-source private EPUB + diagnostic ZIP and X4 read-through before considering release.

The QA5 package `dev.nooir.mihonqa8.foss` and label `MihonNooir QA8` coexist with signed official v1.0.16 and prior QA1–QA4; updater is off in QA5's disposable build. Do not confuse QA5 with the signed production APK.

## QA6 — Panels+-inspired independent frame-confidence detector (5 Nov 2026)

QA6 contains the **draft PR #68** experimental Kotlin component evidence pass *in front of* QA5's three overlapping-row rescue. Existing row-first, dark-framed, slanted and text-safety detectors run first, unchanged. If they all fail, frame-confidence uses an ephemeral half-resolution thumbnail, estimates page-background median from the outer ring, extracts eight-connected high-contrast components, scores straight/slanted frame sides, rejects small/overlapping/sparse or insufficiently framed candidates, demands >=90% source-ink coverage and rejects potential shared speech balloons before any crops. **Only when it still fails** does the original three-overlap-row rescue execute. Row by Row and normal EPUB/CBZ exports remain unchanged. QA6 has isolated package `dev.nooir.mihonqa8.foss`, label `MihonNooir QA8`, updater off only in disposable QA source, independently of official v1.0.16 and QA1–QA5.

The research concepts are attributed to MIT-licensed Panels+ (KristanLaimon), but no implementation source has been copied. Private Python preflight of 45 *wholly unsplit* One Piece source thumbnails predicted cautious framed recovery on ordinals **25,40,80,140,145**. These are **unverified** until exact-code Android QA6 has green full workflow and a new same-source private EPUB plus diagnostics are examined. New false cuts, missing speech, pixel loss or substantive performance regressions block merging. **Do not release.**

## QA7: final fitted-frame readability (5 Nov 2026)

Experimental QA7 is built from draft PR #70 on top of all QA6 detector improvements. Only **Panel by Panel** exports get the new final-slice postprocessor. It computes each crop's scaled-to-fit smaller dimension using the actual requested device target view, with **5mm ~43 X4-equivalent px hard** and **10mm ~87 X4-equivalent px soft** thresholds. This is a **readability proxy** for non-X4 devices, NOT their physical pixel density. Under 5mm, only neighboring aligned source regions can merge; if no safe neighbor exists, keep the real crop. At 5–10mm, merge only sparse borders/decorative strips; preserve substantial framed panels. All merged pixels are included in the union. After that, >2/3-source-height full-width rows on an already multi-view page can become two ordered reading views 0–56% and 44–100% of that row, with **12% deliberate artwork-protecting overlap**. Single-page art, protected text/sparse pages, narrow real panels, heavily overlapping diagonal slices, Row by Row, and WEBTOON bypass.

This is experimental, not the official 1.0.17 release. Use the exact green CI run artifact `mihonnooir-v1.0.17-large-row-qa8-parallel`, extract `app-arm64-v8a-foss.apk` to REDMAGIC, and leave official v1.0.16 and QA1–QA6 installed. Compare the *same* privately owned original One Piece against QA6 1,041 exported frames, especially 26 oversized row sources and small 2mm footers source 197 and 201; count actual render slices and visually check for dialogue cuts, repeated art and false merges. Do not merge until phone/export/X4 QA.

## QA8: genuine second-look before conditional oversized-row fallback (5 Nov 2026)

QA8 is a separate experimental app on draft PR #72; its package is `dev.nooir.mihonqa8.foss`, label **MihonNooir QA8**, versionName **1.0.17-large-row-qa**. It includes every QA7 detector/safe tiny-fragment merge. When a detector-accepted *full-width* row still occupies >50% of original page height, the Android exporter tries ONE bounded (<=600x900) per-row grayscale rescan with the full existing confident panel pipeline, rejecting three-overlap-row fallback, text or unsafe regions. True inner panels must cover **every pixel** of the original row's source rectangle; false-positive candidates that omit borders/art/speech are rejected. If no safe panels, >60% tall rows get overlapping 0–56/44–100 views only if not one strongly enclosed illustrated panel. 50–60% rows additionally require poor final-display occupancy (<55%) in the selected PORTRAIT/LANDSCAPE/AUTO_FIT mode. Same 12% duplicate overlap. Previously safe panel results and Row by Row remain unchanged.

## QA9: absorb isolated near-empty scan headers/footers (5 Nov 2026)

**QA9 is experimental (draft PR #74).** The new package ID is `dev.nooir.mihonqa9.foss`, launcher `MihonNooir QA9`, versionName `1.0.17-sparse-edge-qa`. This is a separately installable, disposable debug-signed QA APK. It contains all QA8 features, but the **Panel by Panel** detector now merges an isolated full-width, near-white scan heading/footer (<=8% of source height) into its immediately adjacent illustrated panels. The check requires both very low dark ink (<3% pixels below 180) and low faint ink (<5.5% pixels below 220), no strongly horizontal frame border (>=70% deep black), and **complete x-axis coverage** by the directly adjoining rectangles. It changes only the reading-view boundary; the original ink, speech, even watermarks remain in the preserved source rectangles. RTL/LTR order is unchanged. Text-rich headers, true framed mini-panels, incomplete/gapped neighbors, OFF, Row by Row and WEBTOON remain unchanged.
